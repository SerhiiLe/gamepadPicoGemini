# Проект для выяснения как работает стандарт HID для gamepad.

Проект рабочий, представляет из себя четыре варианта gamepad, так как единого стандарта HID не существует.

- Совместимый с [Linux/Steam](#linuxsteam) (зажатие X при старте, цвет Циан)
- Совместимый с [Android](#android) (зажатие A при старте, цвет Оранжевый)
- Совместимый с [Nintendo Switch](#nintendo-switch) (зажатие B при старте, цвет Красный)
- Совместимый с протоколом [Sony DualShock 4](#sony-dualshock-4) (зажатие Y при старте, цвет Белый / Lightbar)

Проект имеет простую и четкую структуру, не перегружен лишними функциями, стабилен в работе. Единственные "лишние" функции это [калибровка](#калибровка) и фильтрация показаний стиков, но это вынесено в отдельный файл.

Так-же есть [альтернативные варианты](#варианты-за-пределами-этого-проекта).

## Реализованно

### Утилита проверки вибро и индикации

Вибро и индикация поддерживаются только в Sony DS4 и Xbox.

Так-же реализована утилита на Python которая может проверить индикацию и вибрацию.
```bash
sudo python3 tools/gamepad_tester.py --gui`
```

или через текстовые меню, так-же позволяет проверить клавиши и стики
```bash
python3 tools/gamepad_tester.py --cli
```

или просто в консоли.
```bash
# Проверка левого мотора (Красный LED, 100% на 1 сек)
python3 tools/gamepad_tester.py --rumble-left 100

# Проверка правого мотора (Синий LED, 100% на 1 сек)
python3 tools/gamepad_tester.py --rumble-right 100

# Проверка обоих моторов (Пурпурный LED, 2 секунды)
python3 tools/gamepad_tester.py --rumble 100 100 --duration 2.0

# Установка цвета Lightbar для DS4 (Зеленый)
python3 tools/gamepad_tester.py --color 0 255 0

# Установка паттерна светового кольца для Xbox 360 (Плеер 1 = 2, Вращение = 10, Выкл = 0)
sudo python3 tools/gamepad_tester.py --xpad-led 2
```

### Калибровка

Калибровка запускается зажатием **центральной кнопки** при включении USB:
1. **Шаг 1 (Замер центров):** Светодиод мигает жёлтым цветом. Стики нельзя трогать. Вычисляется точная нейтраль каждого потенциометра.
2. **Шаг 2 (Замер крайних точек):** Светодиод плавно пульсирует маджентой (фиолетовым) в течение 6 секунд. Пользователь вращает стики по максимальной окружности. Фиксируются минимальные и максимальные значения каждого АЦП.
3. **Шаг 3 (Сохранение):** Данные валидируются и записываются во флеш-память RP2040 (эмуляция EEPROM с проверкой сигнатуры `magic = 0x47504144 // "GPAD"`).
4. **Шаг 4 (Завершение):** Светодиод трижды мигает зелёным цветом, и контроллер переходит в нормальный рабочий режим.

### Linux/Steam

Основная проблема этого варианта, как и следующего, это количество кнопок и осей. Кроме обычных сейчас A B X Y ещё должны быть C Z. Они занимают фиксированное место в порядке клавиш и если делать, как я в начале, без пропусков на эти клавиши, то порядок ломается, а часть кнопок просто не работает.

Порядок осей тоже имеет значение: X Y - левый стик, rX rY - правый стик. Отдельным блоком определяются курки-триггеры - Z - левый, rZ - правый.

Обратная связь в виде управления светодиодом или вибрации не поддерживается.

Активация этого режима - при включении надо зажать кнопку X, светодиод будет гореть тусклым сине-зелёным цианом.

### Android

Такие-же пропуски на клавиши C Z, как у версии под Linux/Steam, но с другим назначением осей. Эти клавиши C и Z оставлены для совместимости с gamepad от Sega. В современных играх они не используются и игнорируются, в репортах они всего 0, то есть не нажаты. Но в некоторых программах для проверки gamepad видят эти кнопки и ожидают нажатия для проверки.

Порядок осей: X Y - левый стик, Z rZ - правый стик. Отдельным блоком определяются курки-триггеры - rX - левый, rY - правый.

Несмотря на такое малое отличие раскладки становятся полностью не совместимыми и не пригодными.

Обратная связь в виде управления светодиодом или вибрации так-же, как и для Linux/Steam не поддерживается.

Активация происходит нажатием A при включении. Светодиод будет гореть тусклым оранжевым.

### Sony DualShock 4

Тут нет пропусков, работает вибрация и управляется светодиод. Но работает только с Linux/Steam. С консолями не работает, так как нужен оригинальные сертификат и серийный номер оригинального gamepad. По Android теоретически должен работать начиная с Android 12, но по факту на Android 14 он не видится.

Расположение осей как у версии под Android.

В этой прошивке установлены заглушки под беспроводное соединение, заряд аккумулятора, гироскоп и тачпад с кнопкой тачпада. Они обязаны быть, но их нет в этом маленьком проекте. Sony сильно нагрузили свои gamepad по сравнению с примитивными от Xbox. Но цены одинаковые из-за сертификатов, которые обязаны покупать производители железок. Без этого они не будут работать с приставками, только с компьютером.

Включается этот режим нажатие кнопки Y при включении. Светодиод будет гореть тусклым белым, пока цвет не измениться командами со стороны компьютера. Он полноцветный и может иметь любой цвет, но по умолчанию он синий.

### Nintendo Switch

Официальные контроллеры Nintendo Switch Pro требуют сложного криптографического обмена, но начиная с версии прошивки 3.0.0 в консоли Nintendo Switch есть нативная поддержка стандартных проводных USB HID контроллеров (протокол **HORI Pokkén Tournament Pro Pad**, VID `0x0F0D`, PID `0x0092`).

Этот режим работает «из коробки» как с самой консолью Nintendo Switch (в док-станции или через USB-C OTG), так и со Steam (который автоматически распознаёт раскладку Nintendo A/B/X/Y). Напрямую в Linux/PC не работает!

Раскладка кнопок физически ориентирована под стандарт контроллеров Nintendo:
- Правая кнопка -> A (подтверждение)
- Нижняя кнопка -> B (отмена / назад)
- Верхняя кнопка -> X
- Левая кнопка -> Y
- Курки и бамперы: L, R, ZL, ZR
- Системные клавиши: Minus (-), Plus (+), L3, R3, HOME.

Активация режима — при включении зажать кнопку B. Светодиод загорится фирменным **красным цветом** Nintendo.

## Варианты за пределами этого проекта

### Проект gamepadPicoXbox360

[Проект на голом Pico SDK](https://github.com/SerhiiLe/gamepadPicoXbox360) работает как надо. Работает всё, определяется в Android. Воспринимается всеми играми без оверлея от Steam. Но не работает с приставками.

### Универсальное решение GE2040-CE

Есть готовая прошивка, которую даже компилировать не надо. [https://gp2040-ce.info/](https://gp2040-ce.info/) Клавиши и стики настраиваются через web, который поднимается через RNDIS драйвер (ethernet over usb). И там тоже есть выбор какой протокол имитировать нажимая клавиши при старте. Но там нет такого управления светодиодом :) Вместо этого там желательно поставить отдельные 4 светодиода и OLED экранчик. Получается круче, но требует более сложной схемы и сборки. Или просто не пользоваться этими дополнительным возможностями. Так-же из интересного - можно подключать дополнительные платы ADC что позволяет сделать полный набор осей с полным разрешением. Есть возможность загружать реальные сертификаты, если их найти на форумах. Но обычно его используют для файтингов с устройствами которое на gamepad совсем не похожи, скорее на баян с кучей кнопок, к каждой привязана последовательность нажатий для разных комбо.

Сравнение и описание от ИИ. И я с ним согласен :smile:

---

В ходе разработки и тестирования было проведено прямое аппаратное сравнение созданной прошивки с ведущим открытым решением для микроконтроллеров RP2040 — фреймворком **GP2040-CE** (OpenStick Community Edition v0.7.12). Оба проекта решают задачу построения USB-контроллера, но используют принципиально разные архитектурные парадигмы.

### Сравнительная матрица характеристик

| Критерий | GP2040-CE (Универсальный фреймворк) | gamepadPicoGemini (Целевая прошивка) |
| :--- | :--- | :--- |
| **Основная концепция** | Модульный «комбайн» для широкого круга пользователей без навыков программирования. | Специализированная прошивка, точно спроектированная под конкретную схему и эргономику. |
| **Архитектурный стек** | Pico-SDK bare-metal, многозадачность на 2 ядрах, стек RNDIS, встроенный Web-сервер, NVS Flash. | Earle Philhower Arduino-Pico core, Adafruit TinyUSB, EEPROM Flash emulation. |
| **Конфигурируемость** | **Динамическая:** переназначение любых GPIO через браузерный Web-конфигуратор (`192.168.7.1`). | **Статическая:** строгая привязка пинов в `config.h`. Любое изменение требует перекомпиляции. |
| **Эмуляция платформ** | Огромное число режимов (XInput, Switch, Switch Pro, PS3, PS4 с ключами, PS5, Keyboard, MD/Genesis). | 4 выверенных профиля (PC/Steam, Android, Sony DualShock 4, Nintendo Switch Pokkén). |
| **Аналоговые стики** | Аддон `Analog` (автокалибровка центра на старте, deadzone, circularity, сглаживание). | Полноценная 2-этапная калибровка Min/Center/Max в EEPROM, раздельное масштабирование полусфер, EMA-фильтр. |
| **Индикация и статус** | В основном декоративная/турнирная (анимации Rainbow, индикация нажатия клавиш, тайминги). | **Функциональная:** отображение активного профиля, нативный Lightbar в DS4, цветовой отклик мощности вибромоторов. |
| **Частота опроса (1000 Гц)**| Железно стабильная (аппаратные прерывания и прямые таймеры Pico-SDK без накладных расходов). | ~999 Гц со статистическими микроколебаниями в пределах 1 мс (накладные расходы цикла `loop()`). |
| **Порог входа / Надежность**| Сложный: обширная, но неочевидная документация; риск «залочить» устройство при конфликте пинов `S1/S2` или шины I2C. | Простой: контроллер готов к игре сразу после прошивки; аппаратный вход в калибровку одной кнопкой. |

### Объективные выводы

1. **Сильные стороны универсального фреймворка (GP2040-CE):**
   * Является идеальным выбором для **массового и коммерческого применения**: конечный пользователь может собрать аркадный стик или хитбокс на готовой плате, подключить в браузере и настроить любую раскладку без среды разработки (IDE) и компилятора.
   * Наличие макросов, профилей и широчайшей совместимости с консолями из коробки.

2. **Преимущества целевой специализированной архитектуры (наш проект):**
   * **Отсутствие избыточности:** Нет «балласта» в виде виртуального сетевого адаптера RNDIS, HTTP-сервера и десятков неиспользуемых драйверов. Контроллер стартует мгновенно и не подвержен сетевым конфликтам хоста.
   * **Глубокая интеграция с аппаратной частью:** Прошивка учитывает физические особенности конкретных потенциометров, диапазон напряжений, инверсию осей и схемотехнику силового ключа вибромотора.
   * **Прозрачность кода:** Каждый байт отчёта, логика Eager Debounce и дескрипторы полностью контролируются разработчиком и открыты для точечной оптимизации под конкретную игру или задачу.

## Архитектурные особенности и что это вообще такое

Изначально проект предназначен для проверки возможности создания нестандартных устройств ввода, но с интерфейсом понятным компьютеру.

Например: А что если вместо стиков прикрутить гироскоп и крутить руками, ногами или другими частями тела вместо стиков? Я попробовал. Работает, но не так хорошо, как я ожидал.

Основная проблема в том, что стики имеют нулевое положение подтянутое пружиной и мертвую зону вокруг центра. Если использовать гироскоп, то вы сами должны ловить этот ноль, что требует тренировки. Кроме того инерция пальцев гораздо меньше и позволяет делать намного более быстрые движения, чем можно крутить целой рукой или тем более жопой. Кроме того есть постоянный дрейф по оси Z. Проще говоря, ось поворачивается синхронно с вращением земли (плоскоземельщикам привет), без дополнительной привязки к компасу это проблема.

Но в целом, так и создаются всякие кинекты, пульты для VR, рули для гонок и пр.

Дальше, с чем я столкнулся, это драйвер. Когда-то такие проекты делали на Arduino Leonardo. Или прошивали второй микроконтроллер в Arduino UNO, чтобы он вместо CDC-ACM (Serial) изображал из себя HID. К счастью я пропустил эти извращения. Первым я начал использовать stm32f103. Там, как и для rp2040 можно использовать несколько вариантов для реализации HID, обычно промышленные геймады делают именно на семействе stm32. Но мне было просто некомфортно с ним. Большая плата, отдельный программатор. Как для отработки концепции неплохо, но для любительской реализации именно геймпада не очень. На rp2040 просто удобнее, а плата zero имеет аж 29 выводов при крошечном размере. И тут тоже, стал вопрос, а как именно писать?

У rp2040 есть как минимум 3 варианта, как писать:
- Официальный MbedOS от Arduino. Позволяет писать тяжелые приложения с многопоточностью и плюшками. Но при этом не удобно делать свои кастомные USB протоколы.
- Фреймворк от earlephilhower для Arduino. Простой и лёгкий фреймворк, который просто заворачивает C framework Pico SDK в C++ объекты Arduino. Собственно на нем и сделан этот проект. Но у него есть ограничения. Он приспособлен под Arduino, CDC-ACM и HID. Остальное пролетает мимо.
- Чистый Pico SDK. Тут нет никаких ограничений, вот железо, делай что хочешь. Я не смог создать Xinput устройство под earlephilhower, но в чистом Poco SDK без проблем. По этому и мой проект gamepadPicoXbox360 и GP2040-CE сделаны на нём.

### Выводы

Реализация gamepad именно как hid устройства имеет мало смысла из-за проблем совместимости с реальными играми. Примерно в 98% случаях понадобится какой-то hid gamepad to xinput программный конвертер: XOutput, x360ce, Steam Input, DS4Windows. Но как концепт для проверки своих идей очень даже да.
