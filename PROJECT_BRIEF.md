# Архитектура проекта: Multi-Protocol USB HID Gamepad (RP2040-Zero)

Данный документ содержит полное описание архитектуры, аппаратных и программных решений, математических алгоритмов фильтрации и протоколов взаимодействия контроллера.

---

## 1. Общее описание и цели проекта

Проект представляет собой универсальный высокоскоростной игровой контроллер (Gamepad) на базе микроконтроллера **Raspberry Pi RP2040** (плата **Waveshare RP2040-Zero**). 

### Ключевые цели:
1. **Решение проблемы фрагментации HID:** В отличие от мышей и клавиатур, единого общепринятого стандарта USB HID для геймпадов не существует. Разные операционные системы (Linux/Steam, Android, консоли) ожидают принципиально разные дескрипторы отчётов, порядок осей и назначение кнопок. Проект объединяет в себе 4 аппаратных профиля в одной прошивке.
2. **Минимальная задержка (1000 Гц):** Опрос USB шины настроен на интервал 1 мс (`bInterval = 1`).
3. **Качественная обработка аналоговых стиков:** Устранение шумов АЦП, сохранение калибровки в EEPROM, преобразование квадратной области стика в круглую (Elliptical Grid Mapping) и радиальная мёртвая зона.
4. **Информативная обратная связь:** Двухуровневая индикация (вибрация моторов и режим работы) на встроенном адресном светодиоде WS2812 и вывод ШИМ на внешний вибромотор (GP18).
5. **Автономная утилита тестирования:** Вспомогательный инструмент на Python для проверки моторов вибрации, RGB Lightbar и квадрантов светодиодов без сторонних зависимостей.

## 2. Аппаратная архитектура (Hardware Layer)

Платформа: **Waveshare RP2040-Zero** (Dual Cortex-M0+ @ 133 МГц, 264 КБ SRAM, 2 МБ Flash).

```
                           +-------------------+
                           |   RP2040-Zero     |
       [USB Type-C] <======| D+/D- USB 1.1     |
                           |                   |
       [WS2812 RGB] <------| GP16 (NeoPixel)   |
  [Rumble Motor PWM]<------| GP18 (PWM Motor)  |
                           |                   |
    [Left Stick X] ------->| GP26 / ADC0       |
    [Left Stick Y] ------->| GP27 / ADC1       |
   [Right Stick Y] ------->| GP28 / ADC2       |
   [Right Stick X] ------->| GP29 / ADC3       |
                           |                   |
 [17 Digital Keys] ------->| GP0..GP15, GP19   | (Active LOW, INPUT_PULLUP)
                           +-------------------+
```

### Назначение выводов (Pinout):
* **Аналоговые оси (12-бит АЦП: 0..4095):**
  - `GP26 (ADC0)`: Левый стик X (`PIN_STICK_LX`)
  - `GP27 (ADC1)`: Левый стик Y (`PIN_STICK_LY`)
  - `GP28 (ADC2)`: Правый стик Y (`PIN_STICK_RY`)
  - `GP29 (ADC3)`: Правый стик X (`PIN_STICK_RX`)
* **Обратная связь:**
  - `GP16`: Встроенный адресный светодиод WS2812 NeoPixel.
  - `GP18`: Выход ШИМ (`analogWrite`) для управления силовым ключом второго вибромотора.
* **Цифровые кнопки (Active LOW с внутренней подтяжкой `INPUT_PULLUP`):**
  - Лицевые кнопки: `GP8` (A), `GP7` (B), `GP9` (X), `GP6` (Y).
  - Бамперы: `GP2` (LB/L1), `GP3` (RB/R1).
  - Курки: `GP0` (LT/L2), `GP1` (RT/R2).
  - Системные: `GP15` (Select/Back/Share), `GP5` (Start/Options), `GP10` (Central/Home/Guide).
  - Нажатия стиков: `GP19` (L3), `GP4` (R3).
  - D-Pad (Крестовина): `GP14` (Up), `GP12` (Down), `GP13` (Left), `GP11` (Right).

## 3. Математика и пайплайн обработки сигналов

Каждый цикл `loop()` контроллер выполняет сквозную обработку входов:

```
[Физические кнопки] ---> [Eager Debounce (10мс)] --------> [Button Mask (17 бит)]
                                                                  |
[АЦП стиков (12 бит)] -> [EMA фильтр] -> [Нормализация] -> [Elliptical Mapping] -> [Radial Deadzone]
                                                                  |
                                                                  v
                                              [Генерация USB HID отчёта (1000 Гц)]
```

### 3.1. Eager Debouncing (Антидребезг с мгновенным откликом)
Для достижения нулевой задержки при нажатии механических контактов используется алгоритм с немедленным срабатыванием и окном блокировки (`DEBOUNCE_DELAY_MS = 10` мс):
1. При первом перепаде уровня из `HIGH` в `LOW` состояние кнопки фиксируется мгновенно (задержка 0 мс).
2. Запускается таймер блокировки на 10 мс, во время которого любые дребезговые колебания контактов игнорируются цифровым фильтром.
3. Это предотвращает ложные двойные срабатывания (chatter), критичные для файтингов и ритм-игр на частоте опроса 1000 Гц.

### 3.2. Экспоненциальное скользящее среднее (EMA Filter)
Аналоговые сигналы потенциометров подвержены высокочастотным шумам АЦП. Для стабилизации отсчетов применяется фильтр:
$$\text{EMA}_t = \alpha \cdot \text{Raw}_t + (1 - \alpha) \cdot \text{EMA}_{t-1}$$
где $\alpha = 0.25$. Это эффективно устраняет джиттер (дрожание) младших бит без ощутимого запаздывания позиции стика.

### 3.3. Эллиптическое отображение: Квадрат $\rightarrow$ Круг (Elliptical Grid Mapping)
Физический механизм аналогового стика ограничен круглым отверстием корпуса (безелем), однако электрически потенциометры формируют декартовы координаты в квадратной плоскости $[-1.0, 1.0] \times [-1.0, 1.0]$. 
Без коррекции стик упирается в диагоналях раньше времени (diagonal clamping) либо срезает значения.

В прошивке применяется отображение:
$$x_{\text{circle}} = u \cdot \sqrt{1 - \frac{v^2}{2}}$$
$$y_{\text{circle}} = v \cdot \sqrt{1 - \frac{u^2}{2}}$$
где $u, v \in [-1.0, 1.0]$ — нормализованные координаты осей относительно центра калибровки. Данное преобразование гарантирует идеальный круговой диапазон с равномерным распределением чувствительности во всех направлениях.

### 3.4. Радиальная мёртвая зона (Radial Deadzone)
Вместо раздельной осевой мёртвой зоны (создающей крестообразный артефакт в центре) вычисляется евклидово расстояние:
$$M = \sqrt{x_{\text{circle}}^2 + y_{\text{circle}}^2}$$
Если $M \le \text{deadzone}$ (по умолчанию 3%), координаты обнуляются. За пределами мёртвой зоны вектор плавно и непрерывно масштабируется от 0 до максимума:
$$\text{Scale} = \frac{M - \text{deadzone}}{1.0 - \text{deadzone}}$$

### 3.5. Плавное нарастание курков (Trigger Ramping)
Так как курки LT/RT выполнены на тактовых кнопках (цифровых), для игр с поддержкой аналогового газа/тормоза реализован программный рампинг:
- Время нарастания от 0 до 255: `TRIGGER_RAMP_MS = 90` мс.
- При отпускании значение линейно возвращается к 0 с той же скоростью.

## 4. Поддерживаемые режимы эмуляции USB HID

Выбор режима осуществляется удержанием соответствующей кнопки в момент подключения контроллера к USB. Настройка сохраняется в EEPROM:

| Кнопка старта | Режим | VID:PID | Цвет LED | Особенности протокола |
| :--- | :--- | :--- | :--- | :--- |
| **Удержание X** | `MODE_PC` | `0x2E8A:0x0013` | Циан (`0, 5, 5`) | Linux Desktop, Steam. Пропуски C/Z (Sega gap), оси X/Y/Rx/Ry, курки Z/Rz. |
| **Удержание Y** | `MODE_DS4` | `0x054C:0x05C4` | Белый (`5, 5, 5`) | Sony DualShock 4 v1. Вибрация, чтение RGB Lightbar, дескриптор 0x05/0x01. |
| **Удержание A** | `MODE_ANDROID`| `0x2E8A:0x0016` | Оранжевый (`8, 3, 0`) | Android/Google HID Spec. Курки на Brake/Gas, правый стик на Z/Rz. |
| **Удержание B** | `MODE_NINTENDO`| `0x0F0D:0x0092` | Красный (`8, 0, 0`) | HORI Pokkén Pad. Нативная работа с Nintendo Switch (Switch OS 3.0.0+). |
| **Удержание Central** | `CALIBRATION` | — | Жёлтый / Маджента | Аппаратная калибровка нейтралей и крайних точек стиков. |

### Подробности протоколов:

#### 1. Режим PC / Linux Desktop (`MODE_PC`)
- **Проблема Sega C/Z Gap:** В подсистеме Linux `evdev` и Steam кнопки 1..6 исторически зарезервированы под аркадную раскладку Sega (A, B, C, X, Y, Z). Если передать кнопки 1..4 подряд без пропусков, кнопка X определяется ядром как `BTN_C`, а бамперы сдвигаются. В отчёте биты 2 и 5 всегда удерживаются равными `0`.
- **Оси:** Левый стик — `X/Y`, Правый стик — `Rx/Ry`, триггеры — `Z/Rz` (`0..255`).

#### 2. Режим Android (`MODE_ANDROID`)
- Соответствует официальной спецификации Google Android Game Controller:
  - Правый стик передаётся через Usage `Z` (`0x32`) и `Rz` (`0x35`).
  - Аналоговые триггеры передаются через страницу Simulation Controls: `Brake` (`0x4F`) и `Accelerator` (`0xC4`).

#### 3. Режим Sony DualShock 4 (`MODE_DS4`)
- Совместим с драйверами `hid-playstation` и `hid-sony` ядра Linux и Steam Input.
- **Handshake (Feature Reports):**
  - `0x12`: MAC-адрес контроллера (15 байт).
  - `0xA3`: Версия прошивки и ревизия чипа (48 байт).
  - `0x02`: Таблица калибровки гироскопа и акселерометра (36 байт).
  - `0x01` (Input Report): Статус батареи установлен в `0x1B` (100% Full, Cable Connected), заглушки тачпада деактивированы (`0x80`).
- **Обратная связь:** Двунаправленный Interrupt OUT Endpoint принимает Report ID `0x05`. Из него извлекаются байты мощности тяжелого/легкого моторов и целевой RGB цвет световой панели.

#### 4. Режим Nintendo Switch (`MODE_NINTENDO`)
- Эмулирует лицензированный контроллер **HORI Pokkén Tournament Pro Pad** (`0x0F0D:0x0092`).
- Не требует аппаратного крипто-чипа аутентификации. Работает на консоли Nintendo Switch в док-станции и через портативный USB-C OTG переходник.
- Компактный 8-байтный репорт:
  - Байт 0..1: 13 кнопок в раскладке Nintendo (A — правая, B — нижняя, X — верхняя, Y — левая).
  - Байт 2: D-Pad (8 направлений: 0..7, нейтраль: 8).
  - Байт 3..6: Оси LX, LY, RX, RY (0..255, центр 128).
  - Байт 7: Служебный байт (0x00).

## 5. Система обратной связи и приоритеты светодиода

Индикация на светодиоде WS2812 работает по строгому приоритету:

```
[Запрос состояния]
       |
       +---> [Вибрация активна?] ---ДА---> Левый = Красный, Правый = Синий, Оба = Пурпурный
       |                                   (Вывод ШИМ мощности на GP18)
      НЕТ
       |
       +---> [Режим DS4 и цвет задан ПК?] ---ДА---> Отображение цвета Lightbar хоста
       |
      НЕТ
       |
       +---> Базовый цвет текущего режима (PC=Циан, Android=Оранж, Switch=Красный, DS4=Белый)
```

## 6. Калибровка аналоговых стиков в EEPROM

Калибровка запускается зажатием **центральной кнопки** (`PIN_BTN_CENTRAL`) при включении USB:
1. **Шаг 1 (Замер центров):** Светодиод мигает жёлтым цветом (200 выборок). Стики нельзя трогать. Вычисляется точная нейтраль каждого потенциометра.
2. **Шаг 2 (Замер крайних точек):** Светодиод плавно пульсирует маджентой (фиолетовым) в течение 6 секунд. Пользователь вращает стики по максимальной окружности. Фиксируются минимальные и максимальные значения каждого АЦП.
3. **Шаг 3 (Сохранение):** Данные валидируются и записываются во флеш-память RP2040 (эмуляция EEPROM с проверкой сигнатуры `magic = 0xDEADBEEF`).
4. **Шаг 4 (Завершение):** Светодиод трижды мигает зелёным цветом, и контроллер переходит в нормальный рабочий режим.

## 7. Утилита тестирования: `tools/gamepad_tester.py`

Для валидации протоколов разработана вспомогательная утилита:
- **Без внешних библиотек:** Работает на стандартных модулях Python 3 (`tkinter`, `fcntl`, `struct`, `glob`).
- **Поддержка Linux evdev Force Feedback:** Корректно упаковывает 48-байтную структуру `struct ff_effect` с учётом 2-байтного паддинга 64-битного ядра Linux и удерживает дескриптор открытым для непрерывной вибрации.
- **Поддержка DS4 hidraw:** Прямая посылка пакетов Report ID 5 для проверки моторов и цвета светодиода.
- **Поддержка Xbox 360 Ring of Light:** Поиск и управление квадрантами светодиодов через `sysfs` (`/sys/class/leds/xpad*/brightness`).
- **Режимы запуска:**
  - Графический интерфейс: `python3 tools/gamepad_tester.py --gui`
  - Текстовое меню: `python3 tools/gamepad_tester.py --cli`
  - Однострочные команды: `--rumble-left 100`, `--color 0 255 0`, `--xpad-led 2`.
